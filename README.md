# niryo_teleop — two-Ned2 joint teleoperation

Teleoperate one Niryo **Ned2** (actor) with another Ned2 (master):

```text
Master Ned2 → driver(master_raw) → /master_raw/joint_states
  → master_joint_state_publisher → /master/joint_states (measured master state)
  → teleoperation_controller     → /actor/joint_cmd (desired actor state)
  → actor_controller             → FollowJointTrajectory → Actor Ned2
Actor Ned2 → driver(actor_raw) → /actor_raw/joint_states
  → actor_joint_state_publisher  → /actor/joint_states (measured actor state)
```

> Full bench procedure, robot prep, and safety rules live in
> [`docs/PHYSICAL_SETUP.md`](docs/PHYSICAL_SETUP.md).

## Tested system

- OS: Ubuntu 24.04 (Noble), x86_64, WSL2
- ROS 2: **Jazzy Jalisco** from `/opt/ros/jazzy`
- Python: system 3.12.3 for ROS; `uv` for project venvs
- Robots: 2× Niryo **Ned2**, official `ned-ros2-driver` bridge in a separate
  workspace at `~/projects/niryo_driver_ws` (rosbridge `:9090`,
  namespaces `master_raw` / `actor_raw`)
- `colcon` lives **inside the project venv** (`uv`); `/opt/ros` and `/usr`
  stay untouched except documented ROS message packages for the driver

## Installation

Terminal 1 — this repo:

```bash
cd ~/projects/niryo_teleop
uv venv --system-site-packages --python /usr/bin/python3.12
source /opt/ros/jazzy/setup.bash
source .venv/bin/activate
uv pip install colcon-common-extensions colcon-ros "pytest==7.4.4"
colcon build
source install/setup.bash
python3 -c "import rclpy, sensor_msgs, trajectory_msgs; print('ros imports ok')"
```

Terminal 1 — driver workspace (one-time; needs the robots' IPs):

```bash
mkdir -p ~/projects/niryo_driver_ws/src && cd ~/projects/niryo_driver_ws/src
git clone https://github.com/NiryoRobotics/ned-ros2-driver.git
cd ~/projects/niryo_driver_ws
uv venv --system-site-packages --python /usr/bin/python3.12 --seed
source .venv/bin/activate
uv pip install colcon-common-extensions colcon-ros "pytest==7.4.4" roslibpy
.venv/bin/python -m pip install "autobahn==23.6.2"
sudo apt install -y ros-jazzy-control-msgs ros-jazzy-controller-manager-msgs ros-jazzy-moveit-msgs
rosdep install --from-paths src --ignore-src -r -y
source /opt/ros/jazzy/setup.bash
colcon build
source install/setup.bash
```

## Running with hardware (one robot; echo master to terminal)

Prep: master calibrated, **learning/compliant mode ON**, reachable
(`ping -c 3 169.254.200.200`).

Terminal 1 — official driver, master only:

```bash
source /opt/ros/jazzy/setup.bash
source ~/projects/niryo_driver_ws/.venv/bin/activate
source ~/projects/niryo_driver_ws/install/setup.bash
ros2 launch niryo_ned_ros2_driver driver.launch.py drivers_list_file:=$HOME/projects/niryo_driver_ws/src/ned-ros2-driver/niryo_ned_ros2_driver/config/master_driver.yaml
```

Terminal 2 — relay:

```bash
cd ~/projects/niryo_teleop
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch niryo_teleop master.launch.py
```

Terminal 3 — echo while moving the master slowly by hand (J1 first):

```bash
source /opt/ros/jazzy/setup.bash
ros2 topic hz /master_raw/joint_states /master/joint_states
ros2 topic echo --field position /master/joint_states
```

`position[]` must track your hand at ~driver rate. Flat values mean the arm
isn't compliant or you're on the wrong topic.

## Running with hardware (dual robot; full pipeline)

Prep: both calibrated; **master compliant, actor stiff (learning OFF)**;
actor workspace clear; note both IPs in
`src/niryo_teleop/config/dual_robot_drivers_list.yaml`.

Terminal 1 — official driver, both robots (~15–25 s to init both bridges):

```bash
source /opt/ros/jazzy/setup.bash
source ~/projects/niryo_driver_ws/.venv/bin/activate
source ~/projects/niryo_driver_ws/install/setup.bash
ros2 launch niryo_ned_ros2_driver driver.launch.py drivers_list_file:=$HOME/projects/niryo_teleop/src/niryo_teleop/config/dual_robot_drivers_list.yaml
```

Terminal 2 — confirm raw interfaces:

```bash
source /opt/ros/jazzy/setup.bash
ros2 topic hz /master_raw/joint_states /actor_raw/joint_states
ros2 action list | grep follow_joint_trajectory
```

Terminal 3 — full chain:

```bash
cd ~/projects/niryo_teleop
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch niryo_teleop full_teleop.launch.py
```

Keep the master **still**: the actor first syncs to the master pose on its own
(~3 s), then the log shows `entering LIVE_TELEOP`. Only then move the master
with small, slow single-joint motions and confirm the follow:

```bash
source /opt/ros/jazzy/setup.bash
ros2 topic hz /master/joint_states /actor/joint_cmd /actor/joint_states
ros2 topic echo --field position /actor/joint_states
```

Shutdown order: Ctrl-C the teleop launch first, then the driver, then power
down the arms.

## Faced issues and solutions

1. **Driver died at import: `TypeError: unsupported operand ... InterfaceClass`**
   (`autobahn/twisted/util.py: peer2str`, `ITransport | IProcessTransport`).
   Root cause: system `zope.interface` 6.1 lacks `InterfaceClass.__or__` and
   shadows the venv's 8.6 through `--system-site-packages` namespace
   packaging. Fix: pin the last `Union`-based release in the driver venv —
   `.venv/bin/python -m pip install "autobahn==23.6.2"` — and always launch
   with that venv activated.
2. **Actor never moved; every goal ABORTED with driver `EXECUTING→CANCELED`
   tracebacks.** Root cause: streaming a new goal at up to 10 Hz while the
   previous one still executed — the robot preempted the old goal and the
   driver bridge calls `canceled()` on a goal that was never cancel-requested,
   which rclpy rejects, so nothing ever completed. Fix: `actor_controller`
   sends only the latest valid command with at most **one outstanding goal**
   (next goal only after the previous result), plus a result-timeout watchdog
   (`goal_result_timeout_sec`) that re-arms the gate. Follow cadence is now
   goal-completion rate, not send rate.
3. **Robot still ABORTED even serialized single goals.** Bisected with a
   manually sent goal (2 s single point → SUCCEEDED) against the failing
   0.2 s stamped goal. Root causes in goal content: sub-second horizons and
   first points at `t=0` are rejected, and workstation-stamped headers are
   rejected while epoch-0 means start-now. Fix: `actor_controller` stretches
   outgoing goals to `min_goal_duration_sec` (1.0 s), builds single-point
   sync moves (never a `t=0` point), and zeroes the outgoing goal stamp
   (`/actor/joint_cmd` itself keeps local stamps).
